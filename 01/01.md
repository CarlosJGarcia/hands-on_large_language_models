# Documentación Técnica: Inferencia de LLM Local con Phi-3 y CUDA

Funcionamiento del script `01.py` ejecutado en la workstation rbauw0006, optimizado para hardware NVIDIA **RTX 3060**.

---

### Especificaciones

El código implementa un flujo de trabajo de procesamiento de lenguaje natural (NLP) utilizando la librería `transformers` de Hugging Face. A continuación, se desglosan los componentes críticos:

### 1. Inicialización de Arquitectura y Pesos

Modelo: Se utiliza modelo Phi-3-mini-4k-instruct, un modelo de parámetros compactos diseñado para una eficiencia extrema sin sacrificar la capacidad de razonamiento.

device_map="cuda": Fuerza la carga de los pesos del modelo directamente en la VRAM de la tarjeta gráfica. Esto permite realizar el paso de propagación hacia adelante (forward pass) utilizando núcleos CUDA en lugar de la CPU.

torch_dtype="auto": Detecta automáticamente la precisión óptima del hardware (probablemente Float16 o BFloat16 para la serie RTX 30), reduciendo el consumo de memoria a la mitad respecto a Float32.

### 2. Configuración de Estrategia de Decodificación

Mediante el objeto GenerationConfig, se parametriza el comportamiento del modelo para evitar inconsistencias
- Técnicamax_new_tokens 500 Límite máximo de iteraciones de la capa de salida.
- do_sample False Implementa Greedy Search. El modelo elige siempre el token con la probabilidad logit más alta, garantizando respuestas deterministas.
- pad_token_ideos_token_id Define el token de relleno. Crucial para evitar errores de segmentación en modelos que no poseen un token pad nativo.


### 3. Orquestación mediante Pipeline

 La función pipeline abstrae la complejidad de la tokenización (convertir texto en vectores numéricos) y la detokenización. Al establecer return_full_text=False, el script extrae únicamente los nuevos tokens generados, descartando el prompt original del usuario.

 Casos de Prueba Multilingües. El script hace cuatro pruebas con el modelo:
